# سبک رفرنس و DNA سبک — از ویدیوی رفرنس تا پریست اختصاصی (Reference Style DNA)

وقتی کاربر ویدیوی رفرنس سبک می‌دهد («مثل این بشه»، «با پای این طراحی کن»، پوشه‌ی references یا هر فایل «سبک X»)،
انتخاب نزدیک‌ترین پریست از ۱۹ سبکِ داخلی **ممنوع** است. رفرنس یک قرارداد است، نه منبع الهام آزاد.
مسیر اجباری: **اندازه‌گیری → خواندن چشمی → پریست اختصاصی → طراحی صحنه‌به‌صحنه → تأیید چشمی → اجرا.**

---

## گام ۱ — اندازه‌گیری DNA (script)

```bash
python <skill>/scripts/stylelearn.py "<ref1>" "<ref2>" --out "<workdir>/ref_dna"
```

خروجی به‌ازای هر رفرنس: `sheet_N.jpg` (شیت ۶×۶ زمان‌دار) و `dna_N.json` شامل:

- `palette` — ۸–۱۰ رنگ غالب با سهم هر رنگ و روشنایی (hex آماده برای `theme`)
- `family` — dark / mid / light (از روشنایی میانگین؛ پس‌زمینه را همین تعیین می‌کند)
- `cuts` — تعداد و میانه‌ی فاصله‌ی کات‌ها + `pacing` (fast < 2.2s / medium / slow) = ریتم صحنه‌ها
- `motion` — میانگین تفاوت فریم‌های پیاپی؛ عدد کوچک = صحنه‌های ساکن با دریفت آرام (سبک اکسپلاینری)
- ابعاد، fps، مدت

همه‌ی شیت‌ها را **ببین** و همه‌ی dna_*.json را بخوان. اعداد بدون نگاه چشمی بی‌معنا هستند.

## گام ۲ — کارت هویت سبک (آنچه اسکریپت نمی‌سنجد)

این‌ها را فقط با نگاه به شیت‌ها تعیین می‌شود؛ هر کدام در پریست یا پلن جا می‌گیرد:

| فیلد | چه می‌پرسد | کجا می‌نشیند |
|---|---|---|
| تایپوگرافی | فونت تیتر/بدنه، وزن، اندازه نسبت به فریم | `theme.display/body` |
| رفتار زیرنویس | جمله‌ی کامل پایین؟ کلمه‌محور کراکی؟ هایلایت کدام رنگ/کلمات؟ | `captions` + پیش‌فرض هایلایت |
| واژگان موتیف | خط‌آرت تک‌ضربه؟ ماکت گوشی با هند-کرسر؟ کارت UI؟ ماسکوت؟ HUD میکرو-لیبل؟ عدد شمارنده؟ | واژه‌نامه‌ی صحنه‌ها در `beats.md` |
| گرامر ساخت | هر جمله = یک صحنه‌ی جدید؟ یا یک بوم که لایه‌لایه کامل می‌شود؟ | ساختار `scene`ها در plan |
| ورود عناصر | self-draw (خط خودکش)؟ pop؟ fade؟ از کدام سمت؟ ترتیب ساخت چه؟ | `scene.draw/glow`، `defaults` |
| رنگ تأکید | کدام رنگ فقط برای «درست/مفهوم کلیدی» و کدام برای «غلط/هشدار»؟ | `theme.primary/secondary/ok` |
| فضای خالی | فاصله‌گذاری جسور (عنصر واحد وسط فریم) یا شلوغِ ساختارمند؟ | چیدمان صحنه‌ها |
| شخصیت صدا | SFX نرم/کم‌تعداد؟ موزیک؟ تیک‌های دیجیتال؟ | `sfxMap`, `sfxGain` |
| عناصر ثابت قاب | نوار پیشرفت بالا؟ شماره‌ی پارت؟ برچسب کوچک گوشه؟ | `progress`, پلن |

## گام ۳ — پریست اختصاصی (Bespoke preset)

یک key جدید در `~/.config/reel-motion-edit/styles.json` بنویس (render.js آن را روی پریست‌های داخلی merge می‌کند؛
در نبودش `styles.json` کنار خود plan هم خوانده می‌شود؛ و `"style": {…}` داخل خود plan هم به‌عنوان پریست آن‌زمان پذیرفته می‌شود).
اسکلت همان ساختار پریست‌های `assets/styles.json` است:

```json
{
  "myrefstyle": {
    "label": "سبک رفرنس ۱ (آزمایشگاه سبز-قرمز)",
    "extends": "hud",
    "css": ".st-myrefstyle .kw.stamp{filter:drop-shadow(0 4px 10px rgba(0,0,0,.2))}",
    "feel": "یک جمله: حس کلی رفرنس",
    "explainer": true,
    "progress": true,
    "bg": {"color": "#17191B", "gradient": "radial-gradient(ellipse 85% 60% at 50% 38%,#24262A 0%,#141517 55%,#0A0A0B 100%)"},
    "theme": {"primary": "#3FD98A", "secondary": "#FF5A5F", "text": "#E8EAEC", "display": "Estedad", "body": "IRANSansX", "mono": "JetBrainsMono", "line": "#C9CDD2", "dim": "rgba(232,234,236,.3)"},
    "defaults": {"title": {"anim": "rise", "scrim": false}, "scene": {"glow": 0.35, "draw": 1.0}, "highlight": {"dim": 0, "pulse": false}},
    "transitions": ["fade", "dissolve", "scan"],
    "captions": "reveal",
    "fx": ["vignette"],
    "sfxMap": {"pop": "digital_blip", "notify": "digital_seq", "whoosh": "soft_whoosh"},
    "sfxGain": -3,
    "intro": "fade",
    "grade": "natural"
  }
}
```

پریست فقط **پوسته** را ست می‌کند (پالت، فونت، captions، ترنزیشن‌ها، fx، کاراکتر SFX، پس‌زمینه‌ی اکسپلینر).
صحنه‌ها را پلن می‌سازد — موتیف‌های سبک (خط‌آرت، ماکت، کارت UI، ماسکوت) با `scene` + `svg`/`items` در plan پیاده می‌شوند.

**فیلد `extends` اجباری است:** موتور ظاهرِ ریزِ هر کامپوننت (کارت سفید نوت، سایه‌های steps، caption ها و…) را به کلاس `st-<نام سبک>` می‌بندد؛ پریست جدیدِ بدون `extends` از همه‌ی آن‌ها محروم می‌ماند و به حالت پایه‌ی تیره برمی‌گردد (متن تیره روی کارت تیره). `extends` را روی نزدیک‌ترین سبک داخلی بگذار تا کامپوننت‌ها همان خانواده را ارث ببرند؛ پالت/فونت/captions خودت را روش بنویس. با `css` (رشته‌ی CSS، خودت با `.st-<key>` namespace کن) فقط همان سبک را ظرافت‌کاری کن (سایه‌ی ملایم‌تر مهر/کال‌اوت روی سبک‌های تخت، وزن ≤۸۰۰).

## گام ۴ — طراحی scene-per-beat مثل رفرنس

بیشتر رفرنس‌های خوب اکسپلاینری «صحنه‌به‌جمله» هستند و این همان چیزی است که پریستِ تنها نمی‌تواند بدهد:

- هر جمله‌ی گوینده = یک صحنه‌ی جدید؛ **یک** عنصر کانونی که با کلمه‌ی متناظرش (`data-at="w:کلمه"`) خودش را می‌کشد/نشان می‌دهد.
- زیرنویس جمله‌ای پایین (یکی از caption style های سبک رفرنس)، تیتر بزرگِ انیمیشنی **ممنوع** (همان قانون حذف تیتر هووک).
- حداکثر ۲ عنصر همزمان؛ فضای خالی جسورانه؛ دریفت آرام به‌جای حرکت‌های تند.
- میکرو-لیبل‌های لاتین مونو (`JetBrainsMono`) فقط وقتی رفرنس دارد؛ برای اصالتِ «دیتا» هستند، نه دکور.

## گام ۶ — آیکون‌های واقعی برندها (وقتی اسم محصول واقعی می‌آید)

اگر ویدیو محصولات واقعی را معرفی می‌کند، **آیکون رسمی/برند** را از اینترنت بگیر — مونوگرام حروف اول فقط آخرین fallback است:

```bash
mkdir -p "<workdir>/icons" && cd "<workdir>/icons"
curl -sf -o cursor.svg "https://cdn.simpleicons.org/cursor/#E2622B"   # simple-icons = CC0؛ <slug> از simpleicons.org
```

- ناموجود در simple-icons؟ لوگوی رسمی از سایت محصول (فقط اگر لایسنس آزاد/فیر-یوز است) یا مونوگرام رنگی.
- مصرف: `icon: "img:icons/cursor.svg"` در کامپوننت‌ها، یا `<image href="file:///<abs path>" …>` داخل svg صحنه.
- کپی‌رایت لوگو: استفاده‌ی ادیتوریال در ریلز معمول و قابل‌قبول است؛ هرگز لوگو/کاراکتر داخل ویدیوی رفرنس کاربر را بازکشی نکن.

## گام ۷ — تأیید چشمی side-by-side

```bash
node <skill>/scripts/render.js "<workdir>/plan.json" styleboard <T> plan
```

فریم رفرنس را **کنار** `styleboard.jpg` بگذار و این‌ها را مقایسه کن: پالت (همسطح روشنایی؟) · وزن/اندازه‌ی تایپ ·
فاصله‌گذاری و مرکز کانون · رفتار زیرنویس. اگر حس رفرنس نیامده، پریست/صحنه را قبل از رندر اصلاح کن —
نه بعد از رندر با ۱۰ تنظیم ریز.

## گام ۸ — اقتباس نه کپی (Adapt, don't copy)

- گرامر سبک (پالت، ریتم، موتیف، تایپ) اقتباس می‌شود؛ **هرگز** لوگو، ماسکوت، کاراکتر یا واترمارکِ داخل ویدیوی رفرنس ردپیگیری، بازکشی یا تقلید مستقیم نمی‌شود (همان قانون ماسکوت در Gotchas).
- رفرنس چندتاست؟ DNA مشترک‌شان را بگیر (پالت/ریتم/موتیف تکرارشونده) و تفاوت‌ها را به‌عنوان «امضای بازگشایی» متغیر نگه دار.
- پریستِ ساخته‌شده را در پیشنهاد ۷بخشی نام ببر («پریست اختصاصی از DNA سبک ۲») تا کاربر بداند سبک از رفرنس خودش آمده.

## چه زمانی این مسیر الزامی است؟

- کاربر فایل/پوشه‌ی رفرنس سبک داده یا گفته «مثل این» → الزامی.
- کاربر فقط یک برند/لوگو/پالت داده → برندکیت کافی است؛ DNA لازم نیست.
- کاربر سبک را از ۱۹ پریست انتخاب کرده → پریست + دو جایگزین نزدیک (روال فعلی).
